Clipboard history that never forgets

Four directions for the Funes popup

All four are the same product: open with Super+V, type, press Enter, get pasted where you were. They differ in density, how much metadata is shown, and how loudly the keyboard model is taught. Proposals 1–3 are buildable with GTK 3 widgets + CSS today; proposal 4 is the stretch target. Toggle theme and accent above — every mock follows the simulated system colors, which is the theming stance: system colors, Funes-owned layout, density and typography.

Design principles

The hand never leaves the keys

Every action has a key. The mouse is a fallback, never the happy path. Shortcuts are visible until you no longer need them.

One glance, one decision

The popup exists for ~800 ms. Ranking and legibility beat features: the right item should be on screen before you finish typing.

Chrome is a tax

No title bar, no toolbar, no buttons that duplicate a shortcut. Pixels go to content, not to decoration.

Native, not neutral

Colors, fonts and accent come from the desktop theme. Spacing, rhythm and the keycap language are ours, so Funes is recognizable on any distro.

Copy is content

URLs, code, colors and images are not generic strings. Typographic and iconic differentiation is cheaper than reading.

Nothing destructive by accident

Del removes one item and is undoable with Ctrl+Z; clear-all always confirms.

Spine

Ships with today's stack Densest

A tightened version of what exists. Single-line rows, a fixed left gutter of quick-select numbers, a right gutter of relative time. The number gutter is the whole idea: the first nine rows are reachable with Alt+1…9 without arrowing, which is the single biggest keyboard win Maccy has and Funes lacks.

Why it works

  • Lowest cognitive cost. Users of the current build lose nothing; they just gain numbers and time.
  • Numbers beat arrows. Target acquisition in one keystroke for the 90 % case (the last few copies).
  • Monospace for code-ish text makes commands, hashes and paths scannable without any badge.

Rules

  • Row height 28 px, 7 px vertical padding; never wraps, always ellipsizes at the end.
  • Numbers only for the first nine visible rows; gutter stays reserved so text never shifts.
  • Right gutter: relative age, 12s / 4m / 1h / yest., tabular figures, fixed width.
  • Pinned items float to the top and show a star instead of a number reshuffle.

GTK 3 notes

  • Gtk.ListBox rows as today; add a leading Gtk.Label with .num CSS class and a trailing dim label.
  • Monospace via Pango attributes chosen by a cheap heuristic (no newline + shell/code-ish charset).
  • Alt+1..9 in _on_key_press; Gdk.KEY_1… mapped to get_row_at_index.
  • Match highlight = Pango.AttrList weight+foreground on the matched span, not markup escaping.

Risks

  • Dense rows punish long CJK/RTL strings; test ellipsis with mixed scripts.
  • Relative time needs a per-minute refresh while visible (cheap; popup is short-lived).
02

Ledger

Ships with today's stack Most legible

The history as a journal: sticky section headers (Pinned, Today, Yesterday, Earlier), two-line rows carrying the content plus a quiet metadata line — kind, source window, size, age. Slower to scan than Spine, far better when you are hunting for something you copied "sometime this morning, from the browser".

Grouped history · actions appear inline on the selected row only

Why it works

  • Time is the real index. People remember when they copied, not the exact string.
  • Provenance disambiguates duplicates — two identical tokens from a terminal and a password field are not the same thing.
  • Actions on the selected row teach shortcuts in place, without a permanent toolbar.

Rules

  • Row = 2 lines, 44 px. Only ~6 rows visible: acceptable because search does the heavy lifting.
  • Headers are non-selectable; ↑/↓ skip them, never a dead stop.
  • Kind chips are lowercase and semantic: url · sql · cmd · color · image · text.
  • Metadata line is truncated first; the content line always wins for space.

GTK 3 notes

  • Gtk.ListBox.set_header_func() gives sticky-ish group headers for free.
  • Requires store columns: kind, source_wm_class, bytes — the one real model change on this page.
  • Source app from the same X call already used by Paster to refocus the previous window.
  • Inline action chips: a Gtk.Box in the row, visible toggled on row-selected.

Risks

  • Kind detection is heuristic; a wrong chip is worse than no chip. Keep the list short and confident.
  • Storing the source app is a privacy-adjacent decision — must be documented and switchable off.
03

Palette

Ships with today's stack Most keyboard-forward

Funes as a command palette. Oversized search line, a row of scope filters cycled with ⇥, and a footer legend that changes with context instead of reciting a fixed mantra. Typing > switches from searching history to running commands (clear, pin, settings, quit), so the tray menu stops being the only place actions live.

Why it works

  • One surface, zero menus. Everything the tray menu does becomes typeable, so the tray is optional.
  • Scopes replace mental filtering. "The link I copied" is one ⇥ away.
  • Contextual legend is the cheapest onboarding there is; it also names the window you will paste into.

Rules

  • Search line 17 px / 44 px tall — it is the primary control, it should look like it.
  • ⇥ next scope, ⇧⇥ previous; scope survives typing, resets on close.
  • Footer shows at most 3 actions + 1 hint; it never wraps, never scrolls.
  • Command mode entered only when > is the first character; ⌫ leaves it.

GTK 3 notes

  • Scopes = a Gtk.Box of toggle-styled labels, not Gtk.Notebook; filtering stays in _reload().
  • Command mode is one branch in _on_search_changed feeding a different row model.
  • Paste-target name: cache the focused window's WM_CLASS when the popup opens (Paster already tracks it).
  • Footer = single Gtk.Label with markup, rebuilt on selection change. No layout thrash.

Risks

  • Two modes in one entry can confuse; the accent-colored > sigil must be unmissable.
  • Scope row costs 32 px of vertical space permanently — consider auto-hiding it until ⇥ is pressed.
04

Atrium

Aspirational Needs compositor + model work

The "if we could do anything" version: a floating, translucent panel split into a narrow list and a live preview. You see the whole clipping — all 40 lines of that SQL, the image thumbnail, the color swatch — before committing. Requires a compositor for blur, real item kinds in the store, and thumbnail caching.

Split view · preview pane replaces the tooltip and the guesswork

Why it works

  • No more truncation anxiety. The reason people paste the wrong thing is that they only saw 60 characters.
  • Usage data helps ranking. "Seen 4 times" is both informative and the basis for frecency sorting.
  • The action list is visible without stealing list space — the pane has room the footer never had.

Rules

  • List column fixed at 300 px; the preview takes the rest, min window 640 px.
  • Preview renders text as monospace, images as thumbnails, colors as a full-bleed swatch with hex/rgb/hsl.
  • Selection changes the preview with a 90 ms crossfade — fast enough to hold-arrow through without flicker.

What it costs

  • Blur/translucency: needs a compositor; requires a solid fallback style when unavailable.
  • Store work: kinds, use counters, thumbnail cache, image payloads on disk rather than SQLite blobs.
  • Rounded floating window under X11 needs an RGBA visual and CSD-style drawing; brittle across WMs.
  • Wider window conflicts with "appears under the pointer and vanishes"; consider 560 px list-only mode when the monitor is small.

Recommended path

  • Ship Spine now; adopt Ledger's grouping and Palette's contextual footer as increments; keep Atrium as the 1.0 target once the store grows kinds.

Icon concepts

Five replacements for the stock edit-paste. Each is a full-color app icon (rounded-square base, flat shapes, legible at 32 px) plus a monochrome symbolic sibling on the 16 px grid using currentColor, so the tray icon inverts correctly on light and dark panels. Shared brand palette: night #151A26 → #303A52, amber #E08E1B / #F2B33D, paper #FFFBF3.

A · Stack recommended

Copies piling up: three offset cards, the newest on top with one amber line. States the product in one shape — history, not paste — and stays readable when the cards collapse into a silhouette at 24 px.
